# 기능 명세

[README로 돌아가기](../README.md)

## F-01 앱 시작과 기록 미리보기

- **목적 / Actor:** 모든 사용자가 두 모드와 상위 기록을 확인합니다.
- **사전 조건:** 앱이 로드되어야 합니다. 랭킹 미리보기에는 `VITE_SUPABASE_URL`과 접근 가능한 API가 필요합니다.
- **정상 흐름:**
  1. 앱이 두 모드 랭킹을 미리 가져옵니다.
  2. Toss `getAnonymousKey()`으로 사용자 식별값을 조회합니다.
  3. 등록 사용자이면 사용자 정보와 나의 기록을 미리 캐시합니다.
  4. 홈에서 기록 미리보기와 `풍선 크게 불기`, `풍선 스피드런`을 표시합니다.
- **예외 흐름:** 사용자 식별 또는 백엔드 조회가 실패해도 모드 선택과 플레이는 계속 허용합니다.
- **출력 / 완료 조건:** 홈 화면이 표시되고 사용자가 플레이 또는 기록장으로 이동할 수 있습니다.
- **권한:** 플레이와 공개 랭킹 조회에는 등록이 필요하지 않습니다.
- **관련 화면·API·데이터:** `home`, `GET /ranking-user`, `GET /ranking`, `GET /my-records`, `ranking_users`, `ranking_scores`.
- **근거:** `src/App.tsx`, `src/hooks/useRankingUser.ts`, `src/components/HomeRecordPreview.tsx`, `src/api/rankingApi.ts`.

## F-02 모드 선택, 마이크 권한과 보정

- **목적 / Actor:** 플레이어가 마이크 입력을 준비하고 게임을 시작합니다.
- **입력:** 모드 선택, 마이크 권한, 약 850ms의 주변 소음 표본.
- **정상 흐름:**
  1. 모드를 선택하면 마이크 사용 목적과 로컬 처리 안내 화면으로 이동합니다. 이때는 권한을 요청하지 않습니다.
  2. 사용자가 `마이크 허용하고 준비하기`를 누르면 `getUserMedia()`를 요청합니다.
  3. 선택적 오디오 제약으로 먼저 요청하고, 지원되지 않으면 `{ audio: true }`로 재시도합니다.
  4. 보정 화면에서 RMS 표본의 하위 80% 평균으로 기준 소음을 계산합니다.
  5. 보정 완료 후 바람 인식 미리보기를 제공하고, 시작 버튼을 누르면 3초 카운트다운을 진행합니다.
- **예외 흐름:** 권한 거부, 미지원 MediaDevices/AudioContext, 입력 시작 오류를 한국어 메시지와 재시도 버튼으로 표시합니다.
- **보안·개인정보:** 오디오 파일을 녹음하거나 서버에 전송하지 않고 브라우저 메모리에서 신호 특성만 계산합니다.
- **구현 상태:** **구현 완료.** 권한 요청은 별도 사용자 행동 뒤에만 발생하고, 보정 콜백이 완료된 뒤 권한 화면으로 돌아와 시작 버튼을 표시합니다.
- **근거:** `src/App.tsx`의 `selectMode`, `mic-permission`, `calibrating`; `src/hooks/useBlowDetector.ts`; `src/audio/microphone.ts`; `src/audio/blowDetector.ts`; `src/audio/blowConfig.ts`.

## F-03 풍선 크게 불기

- **목적 / Actor:** 플레이어가 한 번의 연속 호흡으로 풍선을 크게 키웁니다.
- **사전 조건:** 모드 선택, 마이크 초기화, 카운트다운 완료.
- **입력:** 보정된 바람 상태와 `0..1` 바람 세기.
- **정상 흐름:**
  1. 시도마다 15종 중 하나의 풍선 에셋을 선택합니다.
  2. 100ms 이상 임계값을 넘긴 첫 호흡부터 시간과 성장을 누적합니다.
  3. 성장 속도는 지속 시간을 중심으로 바람 세기에 따라 `0.84..1.16`배 보정됩니다.
  4. 엔진이 호흡 종료를 판단하면 700ms 정착 애니메이션을 재생합니다.
  5. 호흡 시간, 평균·최대 바람 세기, 풍선 점수와 최종 풍선을 결과로 생성합니다.
- **예외 흐름:** 시작된 호흡 중 앱이 숨겨지면 시도를 종료하고 `interrupted` 화면에서 재시도를 요구합니다.
- **출력:** 의료 단위가 아닌 호흡 시간과 0~9,999 범위의 재미용 풍선 점수입니다.
- **완료 조건:** 첫 호흡 종료 뒤 결과 화면으로 이동하며 두 번째 호흡은 같은 시도를 연장하지 않습니다.
- **구현 상태:** **부분 구현.** `BlowDetector`는 약한 신호를 350ms 동안 `ending`으로 유지하지만, 크게 불기 엔진은 `state === 'blowing' && hasStrongSignal`이 아니면 즉시 정착을 시작합니다. 따라서 짧은 입력 저하를 같은 호흡으로 유지하는 감지기 유예가 이 모드에 적용되지 않습니다.
- **근거:** `src/game/BalloonEngine.ts`, `src/game/rules.ts`, `src/audio/blowDetector.ts`, `src/game/types.ts`.

## F-04 풍선 스피드런

- **목적 / Actor:** 플레이어가 30초 동안 최대 50개의 풍선을 완성합니다.
- **사전 조건:** 모드 선택, 마이크 초기화, 카운트다운 완료.
- **정상 흐름:**
  1. 게임 진입 시 30초 타이머가 시작됩니다.
  2. 바람이 감지되는 동안 활성 풍선이 성장합니다.
  3. 호흡이 멈추면 풍선 크기는 유지되고 다음 호흡에 이어서 성장합니다.
  4. 완성 반지름에 도달하면 풍선을 완료 목록에 넣고 마지막 완성 시간을 기록합니다.
  5. 직전과 같은 에셋을 피한 새 풍선을 다른 스폰 레인에 생성합니다.
  6. 완성 풍선은 부력·벽·상호 충돌·압축 물리를 적용받아 상단부터 쌓입니다.
  7. 활성 플레이 시간 30초가 되면 미완성 풍선을 제외하고 결과를 생성합니다.
- **예외 흐름:** 앱이 숨겨지면 엔진을 일시정지하고 복귀 시 재개하므로 숨겨진 시간이 타이머에 포함되지 않습니다.
- **출력:** 완성 개수, 마지막 풍선 완성 시간, 총 불기 시간, 완성 풍선 목록.
- **근거:** `src/game/BalloonEngine.ts`, `src/game/physics/physics.ts`, `src/game/rules.ts`, `src/game/balloons/createBalloon.ts`.

## F-05 결과 확인과 랭킹 저장

- **목적 / Actor:** 플레이어가 결과를 보고 원할 때 최고 기록을 저장합니다.
- **정상 흐름:**
  1. 결과 화면은 모드별 주요 기록과 재미용 기록 안내를 표시합니다.
  2. 이미 등록된 사용자는 결과 진입 시 점수를 자동 제출합니다.
  3. 미등록 사용자는 별명을 2~15자로 등록한 다음 현재 점수를 제출할 수 있습니다.
  4. 서버가 반환한 최고 점수와 모드별 시간 기록을 화면과 로컬 캐시에 반영합니다.
  5. 사용자는 다시 도전, 홈, 기록장으로 이동할 수 있습니다.
- **예외 흐름:** 사용자 키 없음, 잘못된 별명, API 오류, 3초 제출 제한을 메시지로 표시합니다. 등록 사용자는 점수 저장을 재시도할 수 있습니다.
- **권한:** 플레이 결과 확인은 공개입니다. 등록과 제출에는 `x-anonymous-user-key`가 필요합니다.
- **데이터:** `ranking_users`에는 사용자 식별·별명, `ranking_scores`에는 모드별 최고 기록만 저장됩니다.
- **근거:** `src/components/ResultScreen.tsx`, `src/api/rankingApi.ts`, `supabase/functions/ranking-api/index.ts`.

## F-06 전체 랭킹, 나의 기록과 별명 변경

- **목적 / Actor:** 모든 사용자는 공개 순위를, 등록 사용자는 자신의 기록과 별명을 관리합니다.
- **정상 흐름:**
  1. 기록장은 크게 불기·스피드런·나의 기록 탭을 제공합니다.
  2. 공개 랭킹은 3초마다 갱신하며 화면에는 1~8위를 구성합니다.
  3. 등록 사용자는 두 모드의 최고 점수, 모드별 시간과 현재 순위를 봅니다.
  4. 별명을 변경하면 고정 4자리 표시 ID는 유지되고 캐시를 갱신합니다.
- **정렬 규칙:** 크게 불기는 점수 내림차순 후 호흡 시간 내림차순, 스피드런은 개수 내림차순 후 마지막 완성 시간 오름차순입니다.
- **예외 흐름:** 비등록 또는 사용자 키가 없는 경우 나의 기록 대신 등록 안내를 표시합니다. 조회·변경 오류는 해당 화면에 표시합니다.
- **근거:** `src/components/RankingScreen.tsx`, `src/api/rankingRules.ts`, `src/api/rankingApi.ts`, `supabase/migrations/008_nongame_anonymous_identity_reset.sql`.

## F-07 결과 이미지 생성

- **목적 / Actor:** 플레이어가 결과 카드 이미지를 앱 안에서 생성합니다.
- **구현된 부분:** 1080×1350 오프스크린 Canvas에 배경, 풍선과 모드별 기록을 그리고 PNG Object URL을 반환합니다.
- **누락된 부분:** `ResultScreen`이 생성 함수를 import하거나 호출하지 않으므로 생성 버튼, 미리보기, 다운로드·공유 경로가 없습니다.
- **구현 상태:** **부분 구현.** 현재 사용자 실행 경로에서 접근할 수 없습니다.
- **근거:** `src/result/createResultSnapshot.ts`, `src/components/ResultScreen.tsx`.

## F-08 모바일 수명주기와 화면 적응

- **목적 / Actor:** 모바일 WebView에서 게임 상태와 자원을 안전하게 유지합니다.
- **동작:** Safe Area를 CSS 변수로 전달하고, 게임 중에만 화면 켜짐을 요청합니다. Canvas는 DPR을 1.5로 제한하고 `ResizeObserver`로 크기를 갱신합니다. 언마운트 시 RAF, ResizeObserver, 이벤트, 오디오 노드와 MediaStream 트랙을 정리합니다.
- **백그라운드 정책:** 크게 불기 진행 중이면 중단, 그 외 게임은 일시정지 후 복귀 시 재개합니다.
- **근거:** `src/hooks/useSafeArea.ts`, `src/hooks/useScreenAwake.ts`, `src/game/BalloonCanvas.tsx`, `src/audio/microphone.ts`.

## F-09 개발용 입력·진단

- **목적 / Actor:** 개발자가 마이크 없이 흐름을 시험하거나 감지 값을 튜닝합니다.
- **입력:** `VITE_BLOW_BALLOON_TEST_MODE=true`, 개발 환경의 `?simulate`, `?debug` 쿼리.
- **동작:** 테스트 모드는 누르고 있는 동안 모의 바람을 생성합니다. 디버그 오버레이는 RMS, 기준값, 바람 세기, 감지 상태와 호흡 시간을 표시합니다.
- **접근 제한:** `?debug`와 `?simulate`는 `import.meta.env.DEV`에서만 활성화됩니다. 환경 변수 기반 테스트 모드는 빌드 환경에서도 켤 수 있으므로 배포 설정 확인이 필요합니다.
- **근거:** `src/hooks/useBlowDetector.ts`, `src/App.tsx`, `.env.example`.

## 검증이 필요한 사항

- Apps in Toss 샌드박스와 실제 iOS/Android에서 마이크 권한·입력 감도·Safe Area를 수동 검증해야 합니다.
- 저장소의 SQL과 Edge Function이 운영 Supabase 프로젝트에 같은 순서로 적용되었는지는 확인할 수 없습니다.
- 결과 이미지 UI 연결은 구현되지 않았습니다.
