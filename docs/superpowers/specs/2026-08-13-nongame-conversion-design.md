# 후우풍선 Apps in Toss 비게임 전환 설계

## 목표

현재 게임 카테고리로 구성된 `blow-balloon`을 Apps in Toss 비게임 미니앱으로 전환한다. 풍선 크게 불기, 풍선 스피드런, 랭킹 기능은 유지하되 사용자 식별·내비게이션·권한 요청·딥링크·Supabase 데이터 모델과 문서를 비게임 기준으로 일치시킨다.

기존 랭킹 데이터는 개발 단계 데이터이므로 전환 마이그레이션에서 초기화한다. 기존 게임용 사용자 식별키와 비게임용 익명 식별키를 연결하거나 이전하지 않는다.

## 확정 범위

- Apps in Toss WebView 유형을 `game`에서 `partner`로 변경한다.
- 비게임 공통 내비게이션 바를 적용한다.
- `getUserKeyForGame()`을 `getAnonymousKey()`로 교체한다.
- 비게임용 익명 식별키를 Supabase 사용자·랭킹 식별자로 사용한다.
- 기존 랭킹 사용자와 점수를 초기화한다.
- 랭킹 기능, 별명, 개인 기록, 두 가지 풍선 모드는 유지한다.
- 앱 내 기능 딥링크 진입점을 추가한다.
- 마이크 권한은 안내 후 명시적인 사용자 동작에서 요청한다.
- 핀치 줌을 비활성화한다.
- 비게임 전환과 직접 관련된 문서와 운영 절차를 동기화한다.

## 제외 범위

- 기존 게임용 식별키와 비게임용 익명 식별키의 사용자 매핑
- 기존 랭킹 데이터 보존 또는 백필
- 토스 로그인 도입
- 결제, 광고, 공유 리워드 도입
- 실제 Apps in Toss 콘솔 설정 변경 및 Supabase 원격 프로젝트 마이그레이션 실행
- 게임 규칙, 점수 산식, 풍선 물리 및 시각 디자인의 재설계

## 앱 설정과 내비게이션

`granite.config.ts`의 `webViewProps.type`을 `partner`로 변경한다. 내비게이션 바는 라이트 테마, 흰색 배경, 앱 로고와 이름, 뒤로가기, 홈 버튼을 표시하는 비게임 기본 구조로 맞춘다.

화면 내부의 자체 뒤로가기 버튼은 Toss 내비게이션의 뒤로가기와 중복되지 않도록 제거한다. 게임 화면의 자체 종료 버튼은 현재 플레이를 종료하고 앱 홈으로 돌아가는 명시적 내부 동작으로 유지할 수 있지만, Toss의 닫기 버튼과 의미가 겹치지 않도록 문구와 접근성 이름을 `플레이 종료하고 홈으로`로 구분한다.

앱의 내부 화면 상태는 기존 단일 상태 머신을 유지한다. Toss 내비게이션 이벤트를 사용할 수 있는 환경에서는 다음 규칙을 적용한다.

- 홈 화면의 뒤로가기: Toss 기본 동작으로 미니앱 종료
- 권한·카운트다운·결과·랭킹 화면의 뒤로가기: 앱 홈으로 이동
- 플레이 중 뒤로가기: 플레이 종료 확인 후 앱 홈으로 이동
- Toss 홈 버튼: 앱 홈 상태로 이동

브리지 이벤트를 사용할 수 없는 일반 브라우저에서는 화면 내 버튼과 기존 상태 전환이 폴백 역할을 한다.

## 사용자 식별과 랭킹

`getAnonymousKey()` 결과의 `hash`를 앱 내부 익명 사용자 식별자로 사용한다. 실제 이름, 전화번호, 이메일 등 토스 계정 개인정보를 요청하거나 저장하지 않는다.

프런트엔드와 Edge Function의 HTTP 헤더는 의미가 명확한 `x-anonymous-user-key`로 변경한다. 코드의 공개 타입과 함수명에서 `GameUser` 같은 게임 전용 표현을 `RankingUser` 또는 `AnonymousUser`로 정리한다. DB 내부 컬럼은 새 마이그레이션에서 `anonymous_key`로 변경한다.

별명은 사용자가 랭킹 공개 목적으로 직접 입력한다. 별명 정책과 금칙어 검증은 유지하며, 입력 화면에 다른 사용자에게 공개된다는 안내와 개인정보 입력 금지 문구를 추가한다.

## Supabase 데이터 모델과 초기화

새 순차 마이그레이션 `008_nongame_anonymous_identity_reset.sql`을 추가한다. 이미 적용된 001~007 마이그레이션을 수정하지 않는다.

마이그레이션은 하나의 트랜잭션 안에서 다음을 수행한다.

1. 기존 `game_scores`와 `game_users` 데이터를 삭제한다.
2. 기존 게임 사용자·점수 RPC 함수를 제거한다.
3. 내부 테이블을 비게임 의미에 맞는 `ranking_users`, `ranking_scores`로 변경한다.
4. `user_key`를 `anonymous_key`, `game_type`을 `ranking_type` 의미로 변경한다.
5. 비게임용 RPC를 생성한다.
6. 기존과 동일한 RLS 강제 적용, 직접 테이블 접근 차단, `service_role` 전용 실행 권한을 유지한다.
7. 랭킹 정렬 인덱스와 사용자별 모드 유일성 제약을 유지한다.

새 RPC 계약은 다음 책임을 갖는다.

- 익명 사용자 조회
- 별명 등록 및 변경
- 최고 기록 제출
- 모드별 랭킹 조회
- 내 기록 조회

Edge Function은 새 RPC만 호출한다. 점수 범위, 제출 속도 제한, 모드별 동점 시간 규칙은 기존과 동일하게 유지한다.

데이터 삭제는 개발 환경 초기화로 명시하며 복구 SQL은 제공하지 않는다. 원격 Supabase에는 사용자가 마이그레이션을 직접 적용해야 하며, 코드 수정 과정에서 자동으로 실행하지 않는다.

## 마이크 권한 흐름

현재 모드 카드 선택 시 즉시 권한을 요청하는 동작을 제거한다. 흐름은 다음과 같다.

```text
모드 선택
→ 마이크 사용 목적과 로컬 처리 안내
→ 사용자가 '마이크 허용하고 준비하기' 선택
→ getUserMedia 권한 요청
→ 주변 소음 보정
→ 준비 완료 버튼
→ 카운트다운과 플레이
```

권한을 거부하거나 마이크를 사용할 수 없어도 홈, 랭킹, 개인 기록은 계속 사용할 수 있어야 한다. 재시도와 홈 이동을 제공하며 오류를 조용히 무시하지 않는다.

## 앱 내 기능과 딥링크

다음 진입점을 지원한다.

- `/lung-test`: 풍선 크게 불기 안내 화면
- `/balloon-rush`: 풍선 스피드런 안내 화면
- `/ranking`: 랭킹 화면

최종 콘솔 스킴은 각각 `intoss://blow-balloon/lung-test`, `intoss://blow-balloon/balloon-rush`, `intoss://blow-balloon/ranking`으로 등록할 수 있도록 문서화한다. 앱은 초기 URL 경로를 파싱해 유효한 진입점만 처리하고, 알 수 없는 경로는 홈으로 폴백한다. 브라우저 히스토리를 외부 이동 목적으로 조작하지 않는다.

## WebView와 UX

`index.html`의 viewport에 `maximum-scale=1`과 `user-scalable=no`를 추가해 핀치 줌을 비활성화한다. 라이트 모드와 Safe Area 처리는 유지한다.

사용자 확인이 필요한 플레이 종료에는 프로젝트 SDK 버전에서 사용 가능한 TDS 모달을 우선 사용한다. 해당 API를 안정적으로 사용할 수 없는 일반 브라우저 폴백은 접근 가능한 앱 내부 다이얼로그로 구현한다. 오류 메시지는 사용자가 다음 행동을 선택할 수 있도록 재시도 또는 홈 이동을 함께 제공한다.

## 오류 처리

- `getAnonymousKey()`가 지원되지 않거나 실패하면 랭킹 등록만 비활성화하고 게임은 계속 이용할 수 있게 한다.
- `INVALID_CATEGORY`는 비게임 콘솔/번들 설정 오류로 분류해 개발 로그에 남기고 사용자에게는 랭킹을 사용할 수 없다는 메시지를 표시한다.
- Supabase 연결 실패 시 캐시된 랭킹·개인 기록을 표시하고 재시도 동작을 제공한다.
- 점수 제출 실패는 게임 결과를 잃지 않으며 결과 화면에서 재시도할 수 있다.
- 마이크 권한 실패는 기록 조회와 랭킹 이용을 막지 않는다.

## 문서 변경

README, 아키텍처, 기능 명세, 정보구조, API 명세, ERD, Supabase 운영 안내 및 프런트엔드 연동 문서를 비게임 용어와 새 식별키·RPC 계약에 맞춘다. 콘솔에서 해야 하는 작업과 원격 Supabase 초기화 절차를 별도 체크리스트로 남긴다.

## 테스트와 검증

기존 순수 로직 테스트는 유지한다. 다음 테스트를 추가하거나 조정한다.

- 비게임 익명 식별키 성공·실패·`INVALID_CATEGORY` 처리
- 딥링크 경로별 초기 화면과 잘못된 경로 폴백
- 모드 선택만으로 마이크 권한을 요청하지 않는지 확인
- 권한 요청 버튼에서만 마이크 권한이 요청되는지 확인
- 익명 식별키가 없을 때 랭킹 등록만 비활성화되는지 확인
- 새 SQL 객체명과 Edge Function RPC 계약의 정적 일치 검증

검증 명령은 다음과 같다.

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm build:web
pnpm build
```

실제 출시 전에는 Apps in Toss 샌드박스와 QR 테스트에서 비게임 내비게이션, 앱 내 기능 스킴, 뒤로가기, 홈 버튼, 마이크 권한 승인·거부, 익명 식별키, 랭킹 초기 등록을 iOS와 Android에서 확인한다.

## 완료 조건

- 코드와 설정에 `getUserKeyForGame` 및 `webViewProps.type: 'game'` 사용이 남지 않는다.
- 비게임용 `getAnonymousKey`로 익명 사용자를 식별한다.
- 신규 마이그레이션이 기존 개발 랭킹 데이터를 초기화하고 비게임용 랭킹 스키마와 RPC를 구성한다.
- 랭킹, 별명, 개인 기록과 두 풍선 모드가 유지된다.
- 마이크 권한은 안내 후 명시적 사용자 동작에서만 요청된다.
- 앱 내 기능 딥링크 3개가 동작한다.
- 자체 내비게이션과 Toss 비게임 내비게이션이 중복되지 않는다.
- 타입 검사, 린트, 테스트와 프로덕션 빌드가 통과한다.
- 원격 콘솔 및 Supabase에 필요한 수동 작업이 문서화된다.
