# 무스크롤 화면 레이아웃 설계

## 목표

`hoo-balloon`의 모든 화면을 하나의 모바일 WebView 뷰포트 안에 표시한다. 문서 스크롤과 내부 스크롤을 모두 제거하되, 필수 정보와 조작 버튼은 화면 밖으로 잘리지 않아야 한다.

## 불변식

- `html`, `body`, `#root`, `.app-shell`은 현재 동적 뷰포트 높이를 넘지 않는다.
- 화면 단위 컨테이너는 `height: 100dvh`와 `overflow: hidden`을 사용한다.
- `overflow-y: auto` 또는 `overflow-y: scroll`을 화면 레이아웃에 사용하지 않는다.
- 홈, 권한, 보정, 카운트다운, 게임, 중단 안내, 결과, 기록장의 필수 콘텐츠와 조작 버튼을 숨기지 않는다.
- Safe Area를 포함한 실제 사용 가능 높이에 맞춰 여백, 글자, 카드와 목록 높이를 단계적으로 줄인다.
- 화면이 낮아져도 터치 버튼은 최소 40px 높이를 유지한다.
- 모달과 키보드가 표시되는 별명 입력 상태에서도 화면 밖 요소에 의존하지 않는다.

## 구현 방식

### 공통 프레임

- 루트 요소의 높이를 `100dvh`로 고정하고 세로 overflow와 overscroll을 차단한다.
- `.app-shell`과 `.screen`에 `height: 100dvh`, `min-height: 0`, `overflow: hidden`을 적용한다.
- 화면 전환 뒤 이전 문서 스크롤 위치가 남지 않도록 구조적으로 문서 스크롤 자체를 없앤다.

### 높이 대응

- 기본 레이아웃은 일반적인 모바일 뷰포트에 맞춘다.
- `760px`, `700px`, `620px` 이하 높이 구간에서 수직 여백, 제목 크기, 일러스트와 카드 높이를 순차적으로 축소한다.
- 콘텐츠를 통째로 `transform: scale()`하지 않는다. 글자 선명도와 입력 좌표를 유지하면서 개별 치수만 줄인다.

### 기록장

- 제목, 설명, 탭, 포디움, 4~8위 목록을 하나의 flex/grid 화면으로 구성한다.
- 포디움과 순위 행이 남은 높이를 나눠 사용하도록 고정 여백을 줄이고 행 높이를 유동적으로 만든다.
- `나의 기록`의 별명 편집 폼까지 같은 뷰포트 안에서 표시한다.

### 결과 화면

- 기존 `overflow-y: auto` 선언을 제거한다.
- 기록 제목, 결과 카드, 랭킹 영역, 재도전·홈 버튼을 세로 flex 레이아웃으로 배치한다.
- 랭킹 등록 폼이 열릴 때 결과 카드 내부 간격을 더 압축하되 입력과 두 액션 버튼을 유지한다.
- 오류 문구가 추가되어도 버튼이 밀려나지 않도록 텍스트 행 수와 내부 여백을 제한한다.

### 기타 화면

- 홈과 게임의 기존 무스크롤 동작을 유지한다.
- 권한, 보정, 카운트다운, 중단 안내는 낮은 화면에서 일러스트와 여백을 먼저 축소한다.
- 종료 확인 모달은 뷰포트 안에서 최대 높이를 제한하고 내부 콘텐츠를 압축한다.

## 검증

- 정적 검사로 `overflow-y: auto`, `overflow-y: scroll`과 스크롤 API 사용이 남지 않았는지 확인한다.
- `320×568`, `375×667`, `390×844`, `430×932` 크기를 기준으로 각 화면의 `scrollHeight <= clientHeight`를 확인한다.
- 홈, 권한, 보정 오류/진행, 카운트다운, 게임, 중단 안내, 결과 기본/등록 폼/오류, 기록장 랭킹/나의 기록/별명 편집 상태를 검사한다.
- 타입 검사, 린트, 테스트와 프로덕션 빌드를 실행한다.

## 범위 밖

- 가로 모드 전용 UI
