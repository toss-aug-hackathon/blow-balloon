# 닉네임 표시 정책 설계

## 목적

랭킹 1~8위에서 닉네임과 고정 4자리 표시 ID가 말줄임표 없이 안정적으로 보이도록 닉네임 입력 범위를 제한한다. 특수문자와 이모지를 차단해 카드 폭, 금칙어 필터, 서버 검증 결과가 일관되게 유지되도록 한다.

## 정책

- 닉네임은 앞뒤 공백을 제거한 뒤 2~6자여야 한다.
- 허용 문자는 완성형 한글(`가-힣`), 영문 대·소문자(`A-Z`, `a-z`), 숫자(`0-9`)뿐이다.
- 공백, 한글 자모 단독, 이모지, 특수기호, 제어문자는 허용하지 않는다.
- 기존 금칙어 정규화 및 차단 정책은 유지한다.
- 화면에는 `닉네임 #1234` 형식으로 표시한다.
- CSS 말줄임표는 비정상 데이터나 예상 밖 글꼴 폭을 위한 최종 안전장치로 유지한다.

## 적용 범위

### 프런트엔드

- 닉네임 정책의 최소·최대 길이를 공용 상수로 정의한다.
- 최초 등록과 별명 변경 입력창을 최대 6자로 제한한다.
- 입력 안내와 오류 문구를 `2~6자`, `한글·영문·숫자만 사용`으로 맞춘다.
- 순수 검증 함수 테스트에 허용 문자, 길이 경계, 공백·자모·이모지·특수기호 거부 사례를 추가한다.

### Edge Function

- 최초 등록과 별명 변경 요청 모두 동일한 2~6자 및 문자 허용 규칙을 적용한다.
- 잘못된 닉네임에는 프런트엔드와 의미가 같은 오류 메시지를 반환한다.
- 프런트 검증을 우회한 직접 요청도 서버에서 거부한다.

### 데이터베이스

- 새 마이그레이션에서 기존 닉네임의 허용되지 않은 문자를 제거한 뒤 앞 6개 문자로 축약한다.
- 정리 결과가 2자 미만이면 `풍선친구`로 교체한다.
- 닉네임 중복은 허용되며 고정 4자리 표시 ID로 사용자를 구분하므로 축약에 따른 충돌은 허용한다.
- 기존 제약과 등록·변경 함수 검증을 완성형 한글·영문·숫자 2~6자 규칙으로 교체한다.
- Edge Function을 우회하더라도 데이터베이스가 같은 규칙으로 잘못된 값을 거부한다.

## 데이터 흐름

1. 입력창이 6자를 초과하는 입력을 막는다.
2. 프런트 검증 함수가 길이, 허용 문자, 금칙어를 검사한다.
3. Edge Function이 동일 규칙을 다시 검사한다.
4. 데이터베이스 함수와 제약이 2~6자 길이를 최종 보장한다.
5. 랭킹 응답은 기존처럼 고정 표시 ID를 결합해 렌더링한다.

## 오류 처리

- 길이 오류: `별명은 2~6자로 입력해 주세요.`
- 문자 오류: `별명은 한글, 영문, 숫자만 사용할 수 있어요.`
- 금칙어 오류: 기존 `사용할 수 없는 별명이에요. 다른 별명을 입력해 주세요.` 유지

## 검증 기준

- 2자와 6자 닉네임은 등록·변경할 수 있다.
- 1자와 7자 닉네임은 프런트와 서버에서 거부된다.
- 완성형 한글, 영문, 숫자 및 이들의 조합은 허용된다.
- 공백, 한글 자모, 이모지, 특수기호는 거부된다.
- 기존 닉네임은 마이그레이션 후 허용 문자만 남고 최대 6자로 축약되며, 2자 미만이면 `풍선친구`가 된다.
- 1~8위 카드에서 6자 닉네임과 `#1234`가 겹치거나 카드 폭을 늘리지 않는다.

## 제외 범위

- 표시 ID 형식 변경
- 닉네임 중복 금지
- 랭킹 카드 구조 변경
- 사용자별 수동 닉네임 정리 UI
