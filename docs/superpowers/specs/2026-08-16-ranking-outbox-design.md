# 랭킹 Outbox 저장 설계

## 목표

iOS와 Android Apps in Toss WebView에서 네트워크 단절, 응답 유실, Supabase 일시 장애가 발생해도 게임 기록을 잃지 않고 사용자에게 재시도 오류를 반복 노출하지 않는다. 다수 사용자가 동시에 접속할 때는 재시도와 랭킹 조회가 한 시점에 몰리지 않도록 한다.

## 저장 흐름

1. 등록 사용자의 게임 결과에 UUID `submissionId`를 발급한다.
2. 사용자 익명 키의 SHA-256 지문과 결과를 Apps in Toss 네이티브 `Storage`에 먼저 저장한다.
3. `localStorage`에도 같은 Outbox를 보조 저장한다. 둘 중 하나만 성공해도 로컬 보관 성공으로 처리한다.
4. 서버 전송이 성공하면 Outbox에서 제거하고 Supabase 응답을 화면과 읽기 캐시에 반영한다.
5. 네트워크, 5xx, 429 오류는 Outbox에 유지하고 지수 백오프와 jitter를 적용해 자동 재전송한다.
6. 입력 오류처럼 재시도로 복구할 수 없는 4xx만 대기열에서 제거하고 사용자에게 안내한다. `USER_NOT_REGISTERED`는 재등록 후 복구할 수 있으므로 만료 전까지 유지한다.

Outbox에는 오디오나 익명 키 원문을 저장하지 않는다. `submissionId`, 익명 키 지문, 랭킹 종류, 점수, 시간, 생성 시각, 재시도 상태만 저장한다. 항목은 7일 후 만료하며 사용자·모드별 최고 후보만 유지한다.

## 동기화 시점

- 결과 생성 직후
- 앱 시작 후 서버 등록 사용자가 확인됐을 때
- 브라우저 `online` 이벤트
- 숨김 상태에서 다시 보이는 `visibilitychange` 이벤트
- 다음 백오프 시간이 됐을 때

백오프는 1초, 2초, 5초, 10초, 30초 이후 최대 5분이며 ±20% jitter를 적용한다. 같은 프로세스의 동기화는 single-flight로 합친다.

## 서버 멱등성과 동시성

`ranking_scores.last_submission_id`에 마지막으로 처리한 UUID를 저장한다. 동일 UUID가 다시 들어오면 쓰지 않고 현재 최고 기록을 반환한다. 다른 제출이 3초 안에 들어온 경우에는 429를 반환해 클라이언트가 조용히 백오프한다.

사용자·모드별 transaction advisory lock과 유일 제약을 유지한다. 따라서 서로 다른 사용자는 병렬 처리되고, 같은 사용자의 중복 요청만 짧은 DB 트랜잭션에서 직렬화된다.

## 사용자 경험

- 로컬 보관 완료: `기록을 안전하게 보관했어요.`
- Supabase 반영 완료: `랭킹에 반영됐어요.`
- 재시도 가능한 장애: 오류 문구 없이 로컬 보관 상태 유지
- 로컬 보관과 직접 서버 저장이 모두 실패하거나 영구 4xx 발생: 사용자 행동이 가능한 오류와 다시 시도 버튼 표시

## 조회 부하

랭킹 화면 폴링은 3초에서 12초로 늘리고 최대 3초 jitter를 적용한다. 문서가 숨겨진 동안은 조회하지 않고, 다시 보일 때 한 번 갱신한다. 동일 랭킹 요청은 기존 single-flight 맵으로 합친다.

## 검증

- Outbox 직렬화, 중복 병합, 최고 기록 압축, 만료
- 백오프와 retryable/permanent 오류 분류
- 동일 `submissionId` 요청 합치기
- 네트워크 실패 후 다음 동기화에서 제거
- iOS/Android 네이티브 Storage 실패 시 `localStorage` 폴백
- 타입체크, 린트, 단위 테스트, Web 및 AIT 프로덕션 빌드
